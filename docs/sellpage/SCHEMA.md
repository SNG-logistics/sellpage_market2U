# Sellpage Builder — Page Contract & Schema

Owner: **Agent A (core)**. B and C import these types; they do not redeclare them.

Source of truth: [`src/features/sellpage/schemas/sellpage.types.ts`](../../src/features/sellpage/schemas/sellpage.types.ts)

## Import from one place

```ts
import type {
  SellpageDocument, SellpageData, SellpageTheme, SellpageSeo,
  SellpageSettings, SellpageVersion, PublishedSellpage, SellpageStatus,
} from '@/features/sellpage/schemas/sellpage.types'
```

Do not define a second `Page`, `Sellpage` or `PageConfig` type anywhere. A
panel or block that invents its own shape drifts from what is actually stored,
and the drift only shows up after a publish.

## `SellpageDocument`

| Field | Type | Notes |
| --- | --- | --- |
| `id` | `string` | Generated by the service. |
| `name` | `string` | Admin-facing label. |
| `slug` | `string` | Unique. Public route is `/s/:slug`. |
| `status` | `'draft' \| 'published' \| 'unpublished'` | |
| `schemaVersion` | `number` | Version the stored data was written with. |
| `draftConfig` | `SellpageData` | Puck data. Editor writes here. |
| `draftTheme` | `SellpageTheme` | |
| `draftSeo` | `SellpageSeo` | |
| `draftSettings` | `SellpageSettings` | |
| `publishedConfig` | `SellpageData \| null` | `null` until first publish. |
| `publishedTheme` | `SellpageTheme \| null` | |
| `publishedSeo` | `SellpageSeo \| null` | |
| `publishedSettings` | `SellpageSettings \| null` | |
| `createdAt` / `updatedAt` / `publishedAt` | `number \| null` | epoch ms. |
| `createdBy` / `updatedBy` | `string \| null` | user id; `null` until auth exists. |

**The separation is the contract:** editing writes `draft*`, `publishPage()`
copies `draft*` into `published*`, and the public route reads `published*`
only. Nothing else may write a `published*` field.

## `SellpageData`

`Data<BlockProps>` from Puck — typed against the blocks actually registered in
`blocks/index.ts`, so adding a block to the registry is what makes it storable.
Shape: `{ root, content: Block[], zones }`.

## `SellpageTheme`

`colors` (primary, secondary, accent, background, surface, text, muted),
`typography` (headingFont, bodyFont, scale), `background`, `maxWidth`
(0 = full bleed), `spacing`.

`maxWidth` defaults to **480** for a new page — a phone-width column, centred
on a wider screen, because sellpages are read on phones. A page published
before themes existed has no stored theme and keeps rendering at **960**:
`legacyPublishedTheme()` in `sellpageService.ts`, not `defaultTheme()`, is its
fallback, so moving the default can never narrow a live page.

Optional, added without a schema bump — absent on every theme saved before
them, and absent renders exactly as before:

| Field | Absent means | Notes |
| --- | --- | --- |
| `backgroundImage` | no photo | Plain URL, through `safeImageUrl` then `cssUrl`. |
| `backgroundImageFit` | `'cover'` | `'cover' \| 'contain' \| 'repeat'`, against the viewport. |
| `backgroundOverlay` | `0` | 0–90, a veil in `colors.background`. Clamped at render. |

`renderer/ThemeFrame.tsx` applies all of it, for the public page and the
editor canvas alike, and exposes the colours as CSS variables (`--sp-primary`,
`--sp-text`, `--sp-spacing`, …) on the wrapper, so blocks can consume the theme
without importing the theme type.

Fonts default to `'Noto Sans Thai', 'Noto Sans Lao', system-ui, sans-serif`.

## `SellpageSeo`

`title`, `description`, `ogImage`, `canonicalUrl`, `noIndex`.
Applied by `hooks/usePageHead.ts`; `ogImage` and `canonicalUrl` are sanitized
before they reach the DOM.

## `SellpageSettings`

`language` (`'th'`, `'lo'`, `'en'`, …) and `tracking`
(`facebookPixelId`, `googleAnalyticsId`, `tiktokPixelId`).

`customHeadHtml` is typed `never` **on purpose**: a raw-HTML head field is a
stored-XSS hole on every published page. Tracking is done with specific,
validated id fields. If a new integration is needed, add another id field —
do not add a free-HTML escape hatch.

## `SellpageVersion`

`id`, `pageId`, `version` (monotonic from 1), `timestamp`, `user`,
`schemaVersion`, `config`, `theme`, `seo`, `settings`.

One snapshot per publish. `restoreVersion()` migrates the snapshot if it was
written under an older schema and writes it to the **draft** — restoring never
publishes.

## Changing the schema

`SELLPAGE_SCHEMA_VERSION` lives in `schemaMigrations.ts`. Bumping it **without**
adding the matching migration step makes every existing page fail to parse and
the public route falls back — `schemaMigrations.test.ts` fails the build if you
do.

To make a breaking change:

1. Append a step to `migrations`:
   ```ts
   {
     from: 1,
     description: 'Button.iconPosition: "before"/"after" -> "left"/"right"',
     migrate: (data) => ({ ...data, content: data.content.map(fix) }),
   }
   ```
2. Bump `SELLPAGE_SCHEMA_VERSION` to `from + 1`.
3. Add a test that an old-shaped document migrates to the new shape.

Migrations must be **pure** and must **not throw** on unexpected input —
return the data unchanged rather than crashing a public page.

Additive, optional fields do not need a version bump; anything that renames,
removes or re-types a stored field does.

## Parsing

`parseSellpageData(value, schemaVersion)` returns
`{ ok: true, data }` or `{ ok: false, reason: 'missing' | 'corrupted' | 'incompatible' }`.
It never throws — the caller renders `FallbackPage`, never a blank page.
